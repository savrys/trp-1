3. ТЕОРЕТИЧЕСКИЕ СВЕДЕНИЯ 
3.1. Django ORM и реляционная база данных 
Django ORM (Object-Relational Mapping) – механизм, позволяющий работать с 
данными реляционной базы данных через объекты Python и классы моделей Django. 
Без ORM приложение может выполнять SQL -запросы непосредственно через 
библиотеку работы с базой данных. Такой подход был использован в ПР7: SQL -
запросы сохранялись в отдельных файлах (sql/queries.sql) или размещались в 
коде, а Django-представления выполняли их через модуль sqlite3. 
Django ORM позволяет описывать структуру данных классами Python и выпо л-
нять типовые операции с помощью методов и атрибутов моделей. Например, вместо 
ручного SQL-запроса к таблице помещений приложение может использовать модель 
Room и выражение: 
Room.objects.all() 
ORM преобразует обращение к модели в SQL -запрос к базе данных и возвр а-
щает объекты, с которыми можно работать средствами Python. 
Основные элементы Django ORM: 
 модель – класс, описывающий сущность предметной области и её данные; 
 поле модели – атрибут, соответствующий столбцу таблицы; 
 объект модели  – отдельная запись базы данных, представленная экземпляром 
класса;

5.4. Выбор стратегии перехода к Django ORM 
Перед созданием моделей необходимо определить, как будут использоваться 
данные, сохранённые в ПР7. Возможны два подхода. 
Вариант 1. Подключение ORM к существующим таблицам.  Модели Django 
настраиваются для работы с уже существующими таблицами посредством параме т-
ра Meta.db_table. При необходимости задаются соответствия между именами 
полей моделей и столбцами таблиц с помощью db_column. 
Этот подход позволяет сохранить существующи е таблицы, но требует точного 
соответствия между их структурой и описанием моделей. Также необходимо о т-
дельно учитывать состояние миграций Django: наличие таблиц само по себе не 
означает, что Django зарегистрировал их создание в истории миграций. Применять  
этот вариант можно только после проверки структуры таблиц и плана миграций: 
нельзя без проверки выполнять обычную миграцию, которая попытается создать 
уже существующие таблицы. 
Вариант 2. Создание таблиц, управляемых Django, и перенос данных.  Су-
ществующая база данных ПР7 сохраняется как источник исходных данных. Django 
использует базу, указанную в настройках DATABASES, и создаёт в ней таблицы для 
ORM-моделей. Затем данные из прежней базы переносятся в новые таблицы. 
Этот подход позволяет не изменять исходн ую базу данных и независимо пр о-

Длинный список удобно разбивать на страницы. В Django для этого служит
